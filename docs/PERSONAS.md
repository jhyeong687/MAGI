# MAGI 인격 설정과 대화 구현

2026-10-28. 프리셋 `naoko-aspects-v2`.

## 원작 설정과 구현 해석

TV판 제13화의 설명과 극장판 프로그램북의 MAGI 항목은 세 컴퓨터가 **아카기 나오코라는 한 사람의 과학자·어머니·여성이라는 측면**을 나눠 이식한 구조라는 기준을 제공한다. 세 명의 서로 다른 전문가를 고용한 위원회로 취급하지 않는다.

확인에 사용한 자료:

- [MAGI 용어 정리](https://wikiwiki.jp/eva-shingeki/%E7%94%A8%E8%AA%9E%E9%9B%86/MAGI%EF%BC%88%E3%83%9E%E3%82%AE%EF%BC%89): 세 인격의 이름과 나오코의 측면을 대응시킨 보조 자료.
- [제13화 장면 정리](https://evangelion.dancing-doll.com/episode/episode-13.html): 리츠코가 설명하는 인격 이식 OS와 나오코에 대한 설명. 원본 영상 자체를 새로 재생한 검증은 아니며, 장면을 정리한 보조 자료다.
- [극장판 프로그램북 스캔 검색 자료](https://ilovemy.cat/downloads/Evangelion/Eva%20megacollection/End%20of%20Evangelion%20Theatrical%20Program%20%28Red%20Cross%20Book%29.pdf): 검색 색인의 일본어 MAGI 항목으로 대응을 교차 확인했다. 원본 PDF 직접 열기와 다운로드는 연결 실패했으므로 전체 스캔을 열람했다고 주장하지 않는다.

과학자=항상 찬성, 어머니=항상 반대, 여성=항상 위험을 감수한다는 대응은 원작 설정으로 취급하지 않는다. 세 측면 모두 같은 사람의 복잡성과 모순을 가질 수 있다. 모든 여성·어머니의 성격에 대한 일반화도 하지 않는다.

**구체적인 장문 답변 말투와 현대적인 질문에 대한 토론 방식은 앱을 위한 해석·확장이다.** 아래 말투, 질문, 우선순위가 원작의 공식 대사나 상세한 성격 규정이라고 주장하지 않는다. 원작 인물의 실제 기억이 있는 것처럼 말하거나, 무관한 현실 질문에 가상의 인물·사건을 끼워 넣지 않는다.

| 인격        | 앱에서 강화한 우선순위                                 | 말투·토론 기여                                                                                                     |
| ----------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| MELCHIOR-1  | 인과, 증거의 성격, 실행이 성립하는 조건, 검증 방법     | 짧고 정확한 분석형 문장. 개념 혼동과 논증의 비약을 지적하고, 어떤 전제·증거가 판단을 바꾸는지 설명                 |
| BALTHASAR-2 | 특정 사람에 대한 돌봄, 관계의 신뢰, 결과를 감당할 책임 | 차분하지만 단호한 비존대 서술형. 추상적인 윤리 문구보다 누가 부담을 떠안고 어떤 지원이 실제로 있는지 확인          |
| CASPER-3    | 개인의 욕망, 애착, 자존심, 감정의 진실성과 자기 선택   | 자기 판단의 주체가 드러나는 솔직한 표현. 도전뿐 아니라 남기·지키기·거절도 가능하며, 타인의 기대와 자기 욕구를 구분 |

## 실제 프로토콜에 반영한 부분

- 인격 프롬프트와 세션을 분리한다. 첫 독립 분석에는 다른 인격이나 자신의 이전 판단을 전달하지 않는다.
- 같은 라운드의 세 응답을 모두 모아 고정한 뒤 다음 라운드에 전달한다. 자기 이전 의견도 그 스냅샷에서 가져와 진행 중 응답이 섞이지 않도록 한다.
- 상호 검증에서 우선 대화 상대를 순환 배정해 세 인격 모두 실제 반론의 대상이 되도록 한다. 둘의 의견을 모두 읽을 수 있으며, 우선 상대의 구체적인 주장에 자기 관점으로 답한다.
- 반박할 문제가 없으면 동의를 인정하고 가치의 가중치가 다른 부분만 설명한다. 갈등·다수결 동조·표 변경·특정 찬반 비율을 강제하지 않는다.
- 재검토에서는 어떤 반론으로 전제나 가치 판단이 바뀌었는지, 또는 왜 바뀌지 않았는지 공개 근거로 설명한다.
- 종합 보고자는 최종 표와 실제 근거만 사용한다. 인격의 라벨만 보고 근거를 꾸미지 않으며, 표가 같아도 관점이 다른 경우 그 차이를 보존한다.
- 설정·토론 기록·개별 판단 창에 원작의 측면과 관점을 표시한다. 메인 답변의 세 최종 의견은 기본으로 펼쳐 실제 문장을 비교할 수 있게 한다.

## 적용과 보존

새 심의는 프리셋 개정 값과 그때의 실제 프롬프트를 저장한다. 종전 기본 프롬프트와 정확히 일치하는 설정만 새 기본값으로 갱신한다. 사용자가 수정한 프롬프트와 언어·토론 횟수·시간 제한 등 다른 설정은 보존한다. 기본값 갱신으로 이전 심의의 답변·표·설정 스냅샷을 자동 변경하지 않는다. 사용자가 명시적으로 보고서 문체 갱신을 요청하면 실제 세 의견과 투표를 보존한 채 종합 답변만 새로 생성하고, 이전 답변도 보관한다.

프롬프트만으로 매 질문에서 성격 차이가 똑같이 크게 나타난다고 보장하지 않는다. 실제 호출로 답변과 반론을 확인하며, 서로 다른 표를 내는 것 자체를 성공 기준으로 삼지 않는다. 구현은 `shared/personas.ts`, `server/orchestrator.ts`, `server/synthesis.ts`에 있다.

## 관제 문체

사용자 요청에 따라 한국어 공개 응답은 -다/-한다 체로 작성한다. 최종 보고는 “조건부로 승인한다. 실행 전에 인력과 공간을 확보하라.”처럼 짧고 단호하게 판정을 통보한다. BALTHASAR의 돌봄은 존댓말 대신 책임과 관계를 살피는 판단 내용으로 드러낸다. 자신감 있는 문체로 불확실한 사실을 확정하거나 실제 행동 권한을 주장하지 않는다. 기존 인격 발언의 원문은 보존한다.
